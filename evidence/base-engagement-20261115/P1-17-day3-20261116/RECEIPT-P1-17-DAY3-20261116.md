## What it is

A NEW edge function `rombot-checkin` (cron-only, verify_jwt false when deployed) plus one UNAPPLIED cron migration. No live function is changed.

- Picks users on local day 3 after their FIRST full assessment (quick checks excluded once `check_kind` exists), Base active, not a test account (`is_test_account`, fail closed), no pending deletion, no red flag, has a plan, no ROMBot message from them in 24 h. Branch C also skips if a session was logged in the last 12 h, or if `user_mobility_schedule.next_check_at` is missing or not in the future (one source with lifecycle W1; no 7 or 42 day math).
- In-app note: new `ai_conversations` row (sport `base`, provider `rombot`, NO title, so no new words in the chat list) + one `ai_messages` row, role `assistant`, content = Stacy's line 1 + "\n" + line 3. The button (label + `/dashboard/my-protocol?src=checkin-d3`) is stored in `context_snapshot`.
- Email fallback, same run, only if ALL: P1-01 opt-in (email_reminders true AND protocol_opt_in_at set, the same rule as lifecycle `explicitOn(pref,"protocol")`, test-pinned), marketing_opt_out not true, valid email, today is a plan day (`PLAN_DAYS`, test-pinned equal to lifecycle `PROTOCOL_DAYS`), Base brand (not BJJ or BB). Otherwise the email is skipped and the in-app note kept.
- Claims in `email_sends`: `checkin-d3-<assessment id>` (note) and `checkin-d3-email-<assessment id>` (email). One of each per assessment, ever.
- Switches: `ROMBOT_CHECKIN_SEND` (new, NOT set) must be exactly "on" for anything to be written; otherwise dry run. The email also needs `LIFECYCLE_EMAILS_SEND` exactly "on" (stays dry; untouched).
